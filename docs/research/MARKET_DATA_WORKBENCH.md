# Market Data Workbench

## Scope and evidence

This is a research view over reconstructed order-level messages, not an exchange matching engine and not a trading recommendation. Public content is generated synthetic data, explicitly distinguished from observed exchange data. FIFO position means arrival order reconstructed from the message stream. Hidden liquidity, undisplayed priority, exchange allocation rules, and a hypothetical participant's fill are not observable here.

## Architecture

`bb-data::l3synth` writes length-prefixed ITCH 5.0 binary messages. `bb-data::l3workbench` passes those messages through the existing `itch::Reconstructor`, retaining its original quality checks, source hash, L2 normalization decisions, and diagnostics. Event index is the zero-based physical frame number, never a timestamp sort. Same-timestamp source ordering is preserved. Event records resolve omitted execute/cancel/delete fields from the pre-event order, then attach post-event BBO.

Book lookups use periodic resting-order checkpoints and forward replay, not a full book copied after every event. The workbench imposes explicit frame/checkpoint bounds rather than silently returning a partial order book. A book at a source frame concerning another symbol is the selected symbol's state as of that frame. Visible orders are capped independently from the L2 total; `orders_truncated` must be inspected before interpreting a displayed order sum. Order age is selected timestamp minus the accepted add/replace timestamp; a replace creates a new priority/lifetime observation.

`bb-analytics::l3` derives L3-native counts, flow, queue, lifetime and observability summaries. Its L2 report delegates to the existing `compute_market` implementation; this avoids a second definition of spread, imbalance, OFI, variance or trade imbalance. Stoikov micro-price is not fitted on the evaluated session. Liquidity recovery is not invented in the absence of an explicitly defined shock window. Native per-event touch depletion/replenishment is separately named and defined.

The public HTTP router precomputes one fixed, fault-free synthetic specification on first access under the existing heavy-read permit, and caches the resulting immutable in-process workbench. It does not accept a file path or load artifacts from disk. Restarting deterministically regenerates it. The CLI precomputes durable artifacts into a new output directory, including the source hash, events, checkpoints, provenance and analytics. This deliberate file-backed choice needs no database migration: existing dataset rows constrain `level` to L2, and registering an L3 source as L2 would misrepresent its identity. The workbench has its own catalogue; ordinary simulation dataset identities, manifests, run configs and golden hashes are unaffected.

## Data classes and licensing

| Class | Use | Distribution |
|---|---|---|
| Generated synthetic L3 | Public demo and reproducible experiments | Redistributable project-generated bytes; not NASDAQ observations |
| Private NASDAQ ITCH or other restricted input | Offline CLI only | Never commit, upload, host, or distribute event-level derived books, messages, or analytics series |
| Hand-built unit fixtures | Decoder, replay and metric checks | Generated in tests; contain no vendor data |

ITCH is a wire format, not a data licence. No grant to redistribute NASDAQ sample data is assumed. See `docs/rebuild/OSS_LICENSES_AND_PROVENANCE.md` and `docs/MARKET_DATA.md`. The hosted restriction is structural rather than a user-controlled provenance flag: only the fixed in-code synthetic generator is reachable by HTTP; all other dataset ids return 404. There is no upload, registration or private artifact path in this router, in either hosted or local profile. Labelling a local file `synthetic` cannot publish it. Private inspection is deliberately CLI-only.

## Generator dynamics

The seeded generator is illustrative, not calibrated; its parameters were chosen so that the public demo exercises the workbench, not to imitate any security or venue. All arithmetic is integer on one SplitMix64 stream, so a seed and configuration determine the bytes exactly. `events` is the exact number of order-flow messages after the prologue (system event, directory, trading action, a 30-order seed book of five levels per side).

- **Latent fair value.** A half-tick random walk (probability 1/16 per step, bounded to ±$2.00 around $100.005). Passive reference prices are the cent ticks just inside it: a one-tick reference spread when fair value lies between ticks, two ticks when it sits on a tick.
- **Message mix per step.** 50% `A`, 4% `F` (MPID-attributed add), 31% `D`, 4% partial `X`, 5% marketable orders, 4% `U`, 2% non-cross `P`. Discrete geometric gaps on a 100 µs lattice approximate memoryless arrivals; one step in eight shares the previous timestamp.
- **Passive adds and replenishment.** Prices are a geometric number of ticks behind the reference (plus a uniform 0–10-tick tail). An add whose limit reaches the opposite touch is a marketable limit order: it executes FIFO up to its limit (one `E`, or 1 in 10 `C`, per resting order hit, at the aggressor's timestamp) and any remainder rests at its limit, so the touch moves toward fair value.
- **Takers.** Unpriced marketable orders sweep at most three touch levels FIFO; their direction leans 7:3 toward fair value relative to the book mid. When fair value has moved through a displayed touch, that side is stale: a step is a marketable order against it with probability 1/4, and half of the cancels/replaces pull its quotes.
- **Cancels and replaces.** Target levels are geometric from the touch (35% continuation), position uniform within the queue; one time in three the farthest level is cleaned up when it lies more than ten ticks beyond the reference. Replaces reprice toward the reference with a fresh size and a new reference number (new priority) and never cross.
- **Balance.** Add sides lean 7:3 toward the side with fewer resting orders; cancels lean toward the side with more. No side's last order is ever executed, so both touches always exist.

Non-cross prints do not consume displayed orders. Optional `--inject-unknown-execute` and `--inject-duplicate-add` append one deliberate reference-integrity violation each after the order flow; both are off by default and must never be described as normal market observations. The `l3synth::dynamics_tests` suite measures the stream through the unchanged `Reconstructor` (not the generator's mirror) and fails on a degenerate session: fewer than 750 best-bid or best-ask changes, fewer than 10 distinct best bids or a best-bid range under 5 ticks, fewer than 3 distinct spreads or a one-tick share outside 10–90%, fewer than 500 execution messages against either side, adds not exceeding 1.5× cancels, cancels not exceeding executions, or a maximum bid/ask resting-order-count gap above the session mean per side. Resulting statistics for the public demo are in `L3_L2_VALIDATION.md`.

## API

All routes are GET under `/api/v1/market` and allow anonymous access to the synthetic demo through the existing authentication, rate limit, daily egress, response-cap and anonymous-cache middleware. Dataset id is `l3-demo`. OpenAPI is generated from the handlers and committed in `web/openapi.json`; browser types are generated in `web/src/api/v1.gen.ts`.

| Route suffix | Parameters | Result |
|---|---|---|
| `/datasets` | none | `{items: Summary[]}` |
| `/datasets/{id}` | none | instrument, simulated venue/session, source SHA-256 version, message counts, quality checks, generator and licensing note |
| `/datasets/{id}/events` | `cursor`, `limit` (default 100, maximum 500), `message_type` (one uppercase letter), inclusive `t0_ns`, `t1_ns`, `from_event_index` | source-ordered event page with opaque cursor and `truncated_by` |
| `/datasets/{id}/events/{event_index}` | `levels` (default 5, maximum 10), `orders_per_level` (default 50, maximum 100) | the event plus the book immediately before and after it: compact best-first depth (FIFO order slots) for both instants, each changed level complete before and after, the referenced order's position before and the added/replacing/still-resting order's position after, completed lifetime, and the same-timestamp messages up to the event |
| `/datasets/{id}/examples` | none | curated example events with their exact deterministic selection rules |
| `/datasets/{id}/book` | required `event_index`, `levels` (default 5, maximum 20), `orders_per_level` (default 20, maximum 100) | best-first L3 queues and complete per-level L2 aggregate |
| `/datasets/{id}/comparison` | none | precise L3 information-loss measures and definitions |
| `/datasets/{id}/metrics` | `max_points` (default 100, range 2–500) | native summaries, bounded native series, existing L2 MarketReport |

Order references and nanoseconds are decimal strings. `price4` is integer quote currency multiplied by 10,000; quantity is integer shares. Queue positions are one-based at their own price; shares ahead excludes the order itself. `bid_shares`/`ask_shares` are whole-book totals. Events can have null fields when the source message does not describe an order or reference resolution failed. The quality manifest is authoritative for quarantined effects; quarantine is never treated as an accepted order change.

Events pages are byte-bounded below the existing anonymous body cap and target at most 256 KiB. Cursors are the existing HMAC-protected cursor format and bind the source hash plus type, time and source-index filters. Time bounds are inclusive session-relative nanoseconds within one day. Invalid bounds/filters/cursors/event indices yield 400; unknown datasets/out-of-range event indices (and, for event details, frames of another symbol) yield 404. Existing middleware can also produce 422 for body cap, 429 for rate limit, or 503 for capacity/egress/database availability. Unknown query parameters are not a publication mechanism.

Measured anonymous response bodies for the 30,034-frame demo (local-profile server on a private database, `curl -s -o /dev/null -w "%{http_code} %{size_download}"`, 2026-11-16): catalogue 5,718 B; summary 5,706 B; events default page 21,315 B; events `limit=500` 106,959 B (`message_type=A` 106,752 B, `message_type=E` 106,861 B, `from_event_index=20000` 108,245 B); book default 19,350 B; book `levels=20&orders_per_level=100` at the last event 179,013 B (the largest possible book response is bounded by 2 × 20 × 100 order rows); comparison 2,090 B; metrics default 45,723 B; metrics `max_points=500` 179,776 B. Every route is below the 256 KiB handler target and the 1 MiB anonymous cap. Added 2026-11-17 (`curl -s <url> -o f; wc -c < f`): examples 1,538 B; event detail default 602 B at #0, 10,467–16,294 B at the five curated examples, 21,987 B at the last event, and 75,345 B at the last event with `levels=10&orders_per_level=100` (the `market_workbench` integration test asserts the latter stays below 256 KiB).

### Event detail semantics

- **Index.** `event_index` is the zero-based physical source frame. `before` is the selected-symbol book after frame `event_index − 1` (`before_event_index`; `null` and an empty book for frame 0) and `after` is the book after frame `event_index`. Both come from one forward replay from the preceding checkpoint that reads no frame after `event_index`; a later message, including a later message with the same timestamp, cannot change the result (`event_detail_is_causal_and_agrees_with_book_and_observations` cuts the source after the event and compares).
- **Same timestamp.** `same_timestamp.events` lists the events sharing the selected event's source timestamp up to and including it, in source order (at most the latest 32; `events_truncated` otherwise), each with the exact before/after totals of the levels it changed. `position` is the event's one-based place among them. Later same-timestamp events are deliberately absent. Equal timestamps are never reordered.
- **Queues.** Depth slots list each level's first `orders_per_level` orders in FIFO order (position = array index + 1) with `orders_truncated` when more rest there. A changed level always lists the selected orders even beyond that prefix, with exact one-based `queue_position` and `shares_ahead` (shares of the orders ahead, excluding the order) computed over the whole queue; skipped positions are visible as gaps. L2 totals (`shares`, `order_count`) always cover the whole level.
- **Orders.** `order_before` is the resting order an `E`/`C`/`X`/`D`/`U` message referenced, before it; `order_after` is the order an accepted `A`/`F` added, the replacement a `U` created, or the referenced order if it still rests. `age_ns` is the event timestamp minus the order's accepted add/replace timestamp. `lifetime_ns` is set only when the event removed or replaced the referenced order (a completed lifetime, equal to the native lifetime observation of that event); a still-resting order's age is a right-censored lower bound, never a lifetime. Quarantined or invalid messages change nothing and name no `order_after`.
- **Numbers.** Nanoseconds and order references are decimal strings (the browser does time arithmetic in `BigInt`); event indices are below 100,000 and therefore exact JSON numbers.

### Curated examples

`/examples` is computed once from the cached workbench by one linear replay. Each example is the earliest event in source order, after both sides first hold at least 100 resting orders, with its stated property; the rule text is returned with it. For the seed-7 demo they are `cancel-ahead` #1,370 (a `D` at position 4 of 7 at the best ask), `partial-execution` #1,342, `replace` #1,371 (a `U` from position 6 of 8 to the back of another ask level), `same-timestamp` #1,448 (sixth of six messages sharing one timestamp) and `level-change` #1,340. `curated_examples_have_their_stated_properties` re-derives every property from the independent event-detail replay (for example, that each order behind the deleted one moved up exactly one position and its shares). The web workbench opens the order-book step on the first example and links each as `/market/l3-demo?example=<id>` (or `?tab=book&event=<index>`).

## Offline use

Build the normal `blackbox` executable. Use a new output directory for each command; existing artifacts are never overwritten.

```sh
# Generated bytes plus workbench/analytics/provenance (no database).
target/debug/blackbox.exe market l3-synth --seed 7 --events 30000 --symbol SYNTH --out data/workbench-synthetic

# Explicit fault demonstration; do not mix with fault-free evidence.
target/debug/blackbox.exe market l3-synth --seed 7 --inject-unknown-execute --inject-duplicate-add --out data/workbench-faults

# Private local inspection; plain or gzip ITCH, explicit bounded prefix.
# Replace the path with your own licensed local input. Never upload this directory.
target/debug/blackbox.exe market workbench --input /private/session.itch.gz --symbol AAPL --max-messages 100000 --out /private/workbench-aapl
```

The HTTP demo needs the normal local server/database configuration, but no dataset registration or demo seed. The API never serves either CLI output directory. The validation experiment and observed command outputs are documented in `L3_L2_VALIDATION.md`.
